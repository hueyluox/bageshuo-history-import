# 本机客户端统计原型：做法与边界

这份记录回答一个实际问题：换语音输入工具后，能不能在新工具里继续看到自己以前的使用积累？

2026 年 11 月，我们在一台 Mac 的网易叭哥说客户端上做过本机原型。旧工具的每日汇总与叭哥说新增用量在原生统计面板相加显示，重启后仍能读取；语音输入及快捷键在修复本机签名、重新授权后恢复。它是一次特定安装环境的验证，没有完成跨版本、跨设备或长期稳定性验证。

## 数据怎么合并

原型保留叭哥说原有统计读取过程，在数据进入统计面板时加入一份独立的旧工具汇总。它没有把虚构的口述文本塞进历史记录，也没有把导入数字冒充服务器返回的使用量。

```text
旧工具每日汇总 ── 校验口径、日期、重复项 ── 本机导入数据
                                             │
叭哥说原有统计 ──────────────────────────────── 合并展示
                                             │
                                   原生统计面板与每日活动图
```

需要同时处理几件事：

1. **口径一致才相加。** 字符数和使用次数需要相同定义；不同日期范围的“本周”和“累计”分别计算。只有总数而没有每日记录时，不编造每日活动图。
2. **时长分开。** 实际录音时长与预计节省时间是不同指标。比如录音 10 分钟、预计省下 20 分钟，不能把 20 分钟导入到录音时长。新的节省时间估算应标明使用的键盘基线。
3. **活动按日期去重。** 同一天在两款工具输入，活跃天数仍是一天。连续天数按同一时区的日期计算，当前日历窗口和全部历史也要区分。
4. **按账号隔离。** 原型将旧汇总限制在目标本机账号下展示；切换账号时不应显示另一账号的导入数据。
5. **新增用量继续累积。** 每次刷新以原生数据加固定导入基线计算，不能把已经相加的面板结果再次作为原生输入，否则会重复累计。

本仓库的 CLI 演示数据格式、批次去重、口径校验和统计合并。`merge` 的输出是一次离线预览；它不包含账号登录、本地持久化或官方客户端适配器。

## 为什么没有直接修改云端统计

在这次本机检查范围内，客户端统计来自服务端查询；没有找到可用于导入其他工具历史汇总的官方写入功能。原型只修改本机展示结果。它不改变网易账号云端的历史用量，也不改变配额、计费或服务端运营统计。

这不等于断言官方内部没有任何写入机制，而是目前没有可确认、可供用户使用的历史统计导入接口。以后如果官方开放导入功能，应优先使用官方实现。

## 本机补丁遇到的实际问题

验证时，统计展示逻辑位于应用内嵌的前端资源中。原型针对该安装版本修改了展示逻辑，并重新打包、签名；旧汇总也只随这份本机原型存在。这不是官方提供的插件接口。应用更新或重新安装可能覆盖改动。

macOS 对主程序、原生动态库与快捷键组件的签名一致性有要求。本次最初的重新签名没有覆盖全部原生组件，导致快捷键失效；统一相关组件的签名，并由用户更新麦克风与辅助功能授权后，输入功能才恢复。由此不能把“统计数字显示正常”当成“整个应用已经验证正常”。

本仓库不发布官方应用文件、反编译资源、签名身份或用户数据，也没有通用补丁安装器。若继续研发客户端适配，应先识别应用版本和资源哈希、保存可恢复原版，再分别验证统计、账号隔离、快捷键、录音、自动输入和重启后的行为。版本不匹配时应停止适配，而不是盲目套用旧改动。

## 适合官方实现的导入流程

统计页选择 CSV / JSON → 预览日期范围、来源与口径 → 检查重复或重叠日期 → 保存到当前账号的本地导入区 → 展示“叭哥说 / 本机导入 / 合计”。每批数据可单独删除，退出账号后隐藏，云端用量继续沿用原来的数据。

这些都是用户自己的汇总数字，不需要原始口述文字或录音。官方若采纳这个流程，就能减少用户修改安装包、处理签名和权限的负担。
